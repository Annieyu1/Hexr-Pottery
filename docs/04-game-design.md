# 04 游戏设计

版本:v0.1 草案 · 2026-10-08

## 1. 总体

- 三个小游戏,三个独立场景;每个内部有难度级,可手选;默认线性递进。
- 统一的"世界观/美术风格",让三个游戏看起来属于同一个产品(风格选项见第 6 节)。
- 画面有趣、清晰、低刺激;不做故事、奖励系统。
- 单次 30 分钟 = 3 × 10 分钟(暂定,待治疗师确认)。

## 2. 三个游戏

### 游戏 1:压力力度分辨
- **刺激**:单指或多指气压强度(0.1–1.0 档位,经校准后映射到"有效档位")。
- **起点**:`Assets/Stage3` 的弱/中/强分拣(物体 = 球/水果,分入三个区域)。
- **任务形态(按范式选择)**:分拣 → 找不同 → 排序(见 03)。
- **难度参数**:基准强度、相邻档位差(ΔI/I)、候选数量、是否涉及多指、辅助级别。
- **交互**:握/捏住物体 → 触觉反馈随物体"重量"或"硬度"变化 → 放进对应位置。
  交互应只依赖已有的 Meta Interaction SDK 抓取;抓握能力有限的患者需要**宽松的抓取判定**(轻触/悬停即可,待确认)。

### 游戏 2:振动频率 / pattern 分辨
- **刺激**:频率 0.1–40 Hz;pattern = 节律(如"短短长")、峰值比等 `[pattern 的具体定义待确认]`。
- **任务形态**:找不同(哪个"嗡嗡"不同)/匹配/按频率高低排序。
- **难度参数**:基准频率、频率差 Δf/f、持续时间、候选数、pattern 复杂度。
- **注意**:不同频率在手指上的主观强度不同,需控制强度一致(等响度校准)。

### 游戏 3:手指定位分辨
- **刺激**:触觉落在某一根/几根手指上。
- **任务形态**:识别刺激落在哪根手指(点屏幕上的手形图,或把物体放到对应手指的颜色处)。
- **难度参数**:手指数量、是否相邻、同时刺激的手指数、刺激强度、视觉提示级别。
- **FlexR**:可用手指运动/弯曲数据来关联"主动探索"(例如患者主动屈伸某指时给刺激)`[待确认 FlexR API 能力]`。

> **2026-10-08 决定**:视觉辅助**只体现在 UI 上**(例如进度条显示当前抓握对应的力度),且**只出现在学习阶段**;不改变物体外观。下面的 L0–L3 分级保留为后续扩展,首版只实现"有 UI 进度条(学习)/ 无(正式)"两档。

## 3. 视觉辅助的渐进淡出(scaffolding)

背景:健康人也发现这套触觉辨别需要**学习时间成本**,开始时不熟悉。目标是最终**纯触觉**判断。建议把"视觉辅助"设成一个独立于难度的**可配置维度**,在不同阶段淡出:

| 辅助级 | 视觉提示 | 目的 |
|---|---|---|
| L0 熟悉 | 触觉强度与视觉量表(颜色条/大小/刻度)**同时、一一对应**显示;可自由重复感受 | 建立"这种感觉 = 这个量级"的概念 |
| L1 提示 | 视觉量表仍在,但不再给出每次的具体值;错误后才显示正确答案 | 开始依赖触觉 |
| L2 弱提示 | 仅在**长时间无作答**或**连续错误**时给出提示 | 提示变成救济 |
| L3 纯触觉 | 无视觉提示;遮住物体或不显示相关信息(如手的触点位置) | 最终目标 |

要点:
- 辅助级是**每个游戏、每位患者独立设置**,也可由治疗师在界面中调整,并**记录到每个试次**(用于分析"视觉依赖度"随时间的变化)。
- "纯触觉"需要真正移除视觉线索:例如物体不显示、用遮挡罩、手部不显示触点位置,避免患者偷看物体大小/颜色来推断答案。
- 如何自动决定何时降一级(例如连续 N 个试次达标)属于**自适应分级**,暂列 Future Work。

## 4. 反馈设计

当前决策:**视觉(文字、特效)+ 声音**;**触觉反馈暂不做**。

### 为什么暂不做触觉反馈
- 被测刺激本身就是触觉,额外的触觉反馈会**混淆**患者对"这是刺激还是反馈"的判断。
- 它是否对康复有用未知;列入 Future Work,等基础版稳定后做对比实验。

### 鼓励性反馈 & 防挫败(设计假设,**需治疗师确认**)
| 原则 | 具体做法 |
|---|---|
| 保持较高成功率 | 通过阶梯法/难度设置,让正确率维持在约 70–80%(见 03);开场几个试次用"明显可分辨"的差值保证成功体验 |
| 错误用中性语言 | 不用"错误/失败/Wrong",用"再试一次 / Let's try again / 这次是 X,感觉一下";错误音效柔和,不用蜂鸣 |
| 错误后给学习机会 | 允许**重新感受**正确与错误的刺激(并列重放),把错误变成学习 |
| 连续失败的保护 | 连续 N 次(如 3 次)错误 → 自动降低难度一档 / 切换到更高辅助级 / 提示治疗师 |
| 强调个人进步 | 展示"和自己上次相比"的进步,不和他人比较;阈值进步用易懂的图形 |
| 强调努力而非结果 | 反馈文字关注坚持和专注("很专注!"),避免空洞过度夸奖 |
| 不设惩罚性计时 | 10 分钟是总时长,不对单个试次做倒计时压迫 |
| 疲劳与不适的出口 | 随时可暂停/退出的明显按钮;治疗师可暂停 |
| 多语言 | 新加坡场景至少英文,可能还有中文、马来、泰米尔 `[待确认]`;文案集中管理便于本地化 |

## 5. 声音与特效
- 声音:正确(柔和上扬音)、错误(中性短音,非警示)、背景(低强度环境音,可关)。
- 特效:粒子、光效、物体动画;强度适中,避免闪烁过强(部分患者可能有癫痫/视觉敏感,需避免高频闪烁)。
- Quest 性能预算:保持稳定帧率优先(通常 72/90 Hz),特效控制粒子数量和 overdraw。

## 6. 美术方向

你要独立做美术,**重要的是选一个"低成本、高一致性、适合 Quest"的风格**。

| 风格 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| 低多边形 + 柔和渐变色 | 资源易找易改、性能好、风格统一容易 | 需要有设计感避免廉价 | **推荐起步** |
| 手绘/卡通渲染(toon) | 亲和、不吓人 | 需要着色器与描边,工作量中 | 想要辨识度时 |
| 写实(接近真实) | 触觉与视觉一致,物体"重量"可信 | 资源成本高,Quest 性能压力大 | 不推荐 |
| 极简几何 + 强色彩 | 最快、最清晰、对视力/认知友好 | 趣味不足 | 评估模式 |

### 6.1 找资产用的关键词(英文,可直接搜)

**风格关键词**
- `low poly stylized`、`stylized 3D`、`soft pastel low poly`、`flat shaded`
- `cozy`、`cozy game art`、`cute stylized props`、`toy-like`、`clay render`
- `toon shader`、`cel shaded`、`outline shader`、`hand-painted texture`
- `minimalist 3D UI`、`soft gradient skybox`、`calm color palette`

**主题/道具关键词**(对应可选世界观)
- 厨房/市场:`fruit basket`、`kitchen props`、`farmers market stall`、`stylized vegetables`
- 花园/温室:`greenhouse`、`garden props`、`stylized plants`、`flower pot`
- 工坊/陶艺:`pottery workshop`、`craft table`、`clay pots`
- 通用:`wooden table`、`shelf`、`jar`、`bowl`

**UI/反馈关键词**
- `game UI kit rounded`、`soft UI kit`、`accessibility large buttons`
- `sparkle particle`、`stars burst`、`soft glow`、`confetti`(注意用量,避免过强闪烁)
- 音效:`soft chime`、`gentle success sound`、`ambient calm loop`、`UI click soft`

**资源站点**(自己核对许可证)
- 模型:Sketchfab(筛 CC 与可下载)、Poly Pizza、Kenney(CC0)、Quaternius(CC0)、Unity Asset Store、itch.io 资产区
- 音效:freesound.org、Kenney audio、Pixabay 音频
- 字体:Google Fonts(选高可读性字体)
- 参考图:Pinterest / Behance 搜上面的风格词,做一个 moodboard

**检索时的筛选条件**
- 许可证优先 **CC0 / CC-BY / 商用允许**;转化阶段要商用,**避免 NC(非商用)**
- 面数低(单个物体 < 5k 三角面)、贴图小(≤1024–2048)
- 格式:glb/gltf 或 fbx;材质简单(便于统一着色)

**统一世界观的备选**(三个游戏共享一个场景主题,换"道具"):
- 厨房/水果市场/花园(Stage3 已有水果和篮子)
- 手工作坊/陶艺
- 温室/植物园

**无障碍与患者友好**:
- 高对比度、大字体、简单色彩(考虑色觉差异);
- 重要信息放在视野中央偏下的舒适区;
- 交互目标足够大,容忍手部抖动;
- 保持场景明亮、低晕动风险(不做强制移动/旋转)。

**资产管理**:
- 每个第三方资产记录来源、许可证、是否要求署名,统一记入 `ASSET_CREDITS.md`(见 06)。
- 已加入 glTFast,推测会使用 glTF/GLB 模型:统一导入规范(单位、材质、LOD)。
