# 05 数据、治疗师界面与临床

版本:v0.1 草案 · 2026-10-08

## 1. 记录哪些数据(我的建议清单,待治疗师增删)

原则:**宁可多记,后续再筛**——存储成本很低,事后补不了。但要区分"必须"与"可选"。

### 1.1 会话级(每次训练一份,`session.json`)
| 字段 | 说明 | 级别 |
|---|---|---|
| `participant_id` | 匿名编码(不含姓名等) | 必须 |
| `session_id`, `session_index`, `date_time` | 会话标识与序号 | 必须 |
| `hand` | 佩戴手:affected / unaffected / both | 必须 |
| `app_version`, `hexr_package_version`, `glove_firmware`, `headset_model` | 复现实验所需版本 | 必须 |
| `difficulty_profile`, `assist_level` | 使用的配置快照 | 必须 |
| `calibration` | 档位-压力校准值、频率校准 | 必须 |
| `game_order`, `game_durations` | 三个游戏的顺序与实际时长 | 必须 |
| `therapist_id`(匿名) | 谁在监督 | 可选 |
| `pre/post_subjective` | 训练前后主观评分(疼痛/疲劳/舒适,如 0–10) | 可选,待治疗师确认 |
| `adverse_events` | 不适、中断原因 | 必须(伦理) |

### 1.2 试次级(每个试次一行,`trials.csv`)
| 字段 | 说明 |
|---|---|
| `session_id`, `game`, `block`, `trial_index` | 定位 |
| `timestamp_start`, `timestamp_end` | 绝对时间戳 |
| `paradigm` | 3AFC/2AFC/sorting/… |
| `difficulty_level`, `assist_level` | 当时难度和视觉辅助级别 |
| `standard_value`, `comparison_value`, `delta`, `weber_fraction` | 刺激量(写给手套的目标值) |
| `fingers_stimulated` | 刺激的手指 |
| `position_of_target` | 正确答案位置/序号(用于分析位置偏差) |
| `response`, `correct` | 反应与是否正确 |
| `reaction_time_ms` | 从刺激呈现(或可作答)到作答 |
| `exploration_count`, `exploration_time_ms` | 重复感受/触碰次数与时长(行为指标) |
| `hints_used` | 是否用了提示/重放 |
| `glove_connected`, `tracking_lost` | 异常标注 |
| `staircase_state` | 当前步长、方向、是否 reversal |

### 1.3 派生指标(每个游戏每次会话)
- 正确率(整体与分难度级)
- 阈值估计(ΔI 与韦伯分数)、reversal 数、阈值估计的置信度/标准差
- 平均/中位反应时间、完成试次数
- 探索行为(平均探索时长)
- 位置偏差(是否总选某位置/某指)
- 视觉辅助依赖度(分辅助级的正确率差异)
- 学习曲线(会话内前半 vs 后半)

### 1.4 运动数据(FlexR / 手部追踪,可选)
- 每指弯曲角度(低频,如 10–30 Hz)、手部位姿;
- 用途:探索策略、动作质量、与触觉表现的关联;
- 代价:文件变大,分析复杂。建议科研版**可开关**,默认记录。`[待确认 FlexR API]`

### 1.5 训练外的临床量表(不在 App 内,但需在研究方案里对应)
候选(需与治疗师/研究方案确认):
- 运动功能:**Fugl-Meyer(FMA-UE)**、Brunnstrom 分期
- 感觉评估:Nottingham Sensory Assessment(或 Erasmus MC 修订版)、Semmes–Weinstein 单丝、两点辨别、本体感觉测试
- 手功能/日常:如 ARAT、Box and Block、Nine-Hole Peg(按研究目标选)
- 患者报告:满意度/可用性(如 SUS)、主观负荷

App 内的数据应能与这些量表的评估时点对齐(`session_index`、日期)。

## 2. 数据格式与存储

- **逐试次 CSV**,每行 flush(崩溃也不丢数据);**会话元数据 JSON**。
- 文件名与目录包含 `participant_id` 与 `session_id`,**不含**姓名。
- 存储位置:Quest 的 `persistentDataPath`;导出方式:USB(adb/文件管理)或治疗师界面导出 `[待确认]`。
- **不联网**(pilot 阶段):没有云同步,没有自动上传;数据备份靠导出流程。
- 数据版本号:在 `session.json` 中写 `schema_version`,以后改字段可兼容。

## 4. 治疗师界面

### 需求(来自你的回答)
- 治疗师需要参与;最好有独立的治疗师界面。
- 手套结合 FlexR,可采集手指运动。

### 候选方案
| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 头显内治疗师面板 | Hub 里隐藏入口(PIN/特定手势),设置参数、查看本次结果、导出 | 开发最省;无需额外设备;不联网即可用 | 治疗师要戴头显或看投屏;界面空间小;不方便同时观察患者 |
| B. 配置文件 + 头显内结果页 | 研究者用 JSON 改配置,拷到设备;结束时显示结果 | 极简,研究版足够 | 治疗师不友好,易出错 |
| C. 局域网伴侣应用(平板/电脑网页) | 头显与治疗师设备在同一 Wi-Fi 内通信;治疗师实时看状态、改参数、暂停 | 临床体验最好;可看患者所见(投屏)+ 数据面板 | 开发量最大;需要处理局域网通信;仍"不联网"但要局域网 |
| D. Quest 投屏 + 头显内面板 | 用 Meta 的投屏/镜像看患者画面,参数仍在头显内改 | 开发量小,治疗师能看到进展 | 依赖投屏设置;参数交互不便 |

**建议分期**:
1. **一期(pilot)**:A + B(头显内面板 + 配置文件)+ 投屏看画面(D);
2. **二期**:C(局域网伴侣应用),在 pilot 反馈后根据治疗师需求设计。

### 治疗师界面功能清单(草案)
- 选择/创建受试者编码,选择手别;
- 选择游戏、难度、辅助级;
- 开始 / 暂停 / 终止会话;实时看当前试次进展(二期);
- 查看本次会话的汇总(正确率、阈值、时长);
- 导出数据;
- 校准向导(压力/频率);
- 手套连接状态与电量(若 API 提供)。

## 5. 双手佩戴问题(记录)

你不清楚双手佩戴是否有助于康复。框架上支持 `hand = affected / unaffected / both`,并在数据里记录。可能的使用方式:
- 仅患侧:标准训练;
- **健侧参照**:先在健侧手感受参照刺激,再在患侧手匹配(需要双手都戴)——有无临床价值待治疗师/文献确认;
- 双手同时:对称/不对称刺激。

→ 先做**仅患侧**,双手模式作为设计选项保留接口,研究价值与临床证据列入 FUTURE_WORK。
