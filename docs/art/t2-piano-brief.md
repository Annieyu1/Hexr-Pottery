# 模型说明：T2 弹琴

版本：v0.1 · 2026-10-20 · 状态：**琴和桌面小道具已建模并导出**（见 `t2-piano.md`）；手套外观、乐谱架未做
用途：给 Blender 会话的交接页。参考图：用户 2026-10-20 提供的"客厅 + 钢琴 + 浮空乐谱"概念图（只作风格参考，不进项目）。

## 1. 任务一句话
患者坐在桌前，患侧手（戴 HexR 手套）放在琴键上。开始时校准，**琴键自动移到患者指尖下面，和真实桌面对齐**。只有中间 5 个白键 C–G 能弹，一根手指对一个键。L1 琴键自己按下，L2 按提示学弹，L3 测试。

## 2. 参考图里取什么、改什么

| 参考图里的元素 | 取 | 改 / 不做 |
|---|---|---|
| 温暖客厅、低多边形、柔和光 | 画风、色调 | **沿用现有书房**（`HexR_StudyRoom.blend`），不另建客厅 |
| 三个八度的电子琴 | 造型：深色外壳 + 白键 + 黑键 | **做成很薄的桌面琴**（见 §3.1），四个八度 |
| 发蓝光的琴键 | 目标键发光 | 发光在 Unity 里换材质，模型只要求可弹的键**单独成物体、只有一个材质槽** |
| 浮空乐谱（音符 + 指法数字、当前音高亮、进度条） | 很好的视觉提示 | **在 Unity / Figma 里做 UI**，不在 Blender 里建（§5） |
| 两只手都戴手套 | 手套外观 | 只有**患侧手**戴手套；手套皮肤是可选项（§4 B） |
| 曲子 Für Elise | — | 现在只能弹 C–G 五个音、一指一键，**Für Elise 弹不了**；曲目用欢乐颂、小星星这类 |
| 书堆、笔筒、绿植、小猫摆件 | 生活感 | 书房已有的道具直接用；可以加"琴谱书"和小摆件（§4 D） |

## 3. 硬性要求（代码依赖）

### 3.1 必须很薄
校准时琴键顶面放在患者**放松的指尖下方约 8 mm**。患者的手指其实就放在真实桌面上，所以琴键顶面几乎和桌面一样高。
- **整台琴高度不超过 12 mm**（从键顶往下）。正常电子琴有 8–10 cm 高，会整个陷进桌子里。
- **琴前沿**（靠患者那边）要低于键顶，不能高出来。患者的手掌、手腕放在琴前面的桌上，会和它穿插。
- 琴后面的面板可以高一些（≤ 3 cm），做一点旋钮、音箱孔装饰。手指碰不到那里。

### 3.2 原点和朝向
- 根空物体 `T2_Keyboard` 的原点在**中间那个可弹键 E 的中线**上，高度在**白键顶面**，前后位置在"**指尖线**"（白键前沿往里 35 mm）。
- 患者在 Blender **−Y** 一侧（正视图就是患者视角），+X 是患者的右手边，+Z 向上。导出后由 Unity 会话核对方向。
- 1 单位 = 1 米，应用缩放。

### 3.3 可弹的 5 个键
- 5 个白键 **C、D、E、F、G**（中央 C 那一组）各是**单独的网格物体**，名字固定为 `Key_C`、`Key_D`、`Key_E`、`Key_F`、`Key_G`。
- 每个键的**原点在键的后沿、顶面、左右居中**（铰链位置）。按下时 Unity 让它绕自身 X 轴转约 4°，前端下沉。
- **每个键只有一个材质槽**，所有白键共用材质 `T2_KeyWhite`。发光是 Unity 把这个键换成发光材质，所以不能和别的部件合并。
- 其余白键合成一个 `T2_WhiteKeys_Static`，黑键合成一个 `T2_BlackKeys`。这些键都不能弹。

### 3.4 尺寸（米）

| 部件 | 尺寸 | 说明 |
|---|---|---|
| 白键间距 | 0.022（键宽 0.0205 + 缝 0.0015） | 和代码默认一致。Unity 按患者指距在 X 方向缩放整台琴（约 0.65–1.6 倍），所以**不要在键上做会被拉变形的细节** |
| 白键长度 | 0.13：指尖线前 0.035，后 0.095 | |
| 白键厚度 | 0.010 | 顶面 z = 0 |
| 黑键 | 宽 0.012 × 长 0.08，顶面高出白键 0.008 | 前端在指尖线后 0.015，不挡手指 |
| 键数 | **四个八度 C2–C6，29 个白键 + 20 个黑键**（2026-10-20 用户要求琴更大、键更多；原来是两个八度），可弹的 C4–G4 在中间 | 加外壳总宽约 0.67 m |
| 外壳 | 底面 z = −0.012；前沿顶面 ≤ −0.004；后面板深约 0.04，高 ≤ +0.03 | 整台深约 0.18 m |

## 4. 资产拆分与优先级

| 编号 | 资产 | 部件 | 优先级 | 预算 |
|---|---|---|---|---|
| A | **薄桌面琴** `T2_Keyboard` | `T2_Case`（外壳 + 后面板装饰）、`T2_WhiteKeys_Static`、`T2_BlackKeys`、`Key_C`…`Key_G` | **必须** | ≤ 3k 三角面，8 个网格物体 |
| B | 手套皮肤（可选） | 在 Meta OpenXR 手模型上画手套贴图：黑色织物 + 蓝色绑带 + 手背的控制盒（硬物，挂在手腕骨骼上） | 次要 | 沿用 T1 手模型流程（`docs/art/t1-hand-texture-brief.md`）。不确定追踪到的手能不能换皮，先问 Unity 会话 |
| C | 琴谱架 / 乐谱板框（可选） | 只做一个木质或亚克力的板框；乐谱内容是 UI | 次要 | ≤ 500 三角面 |
| D | 桌面小道具 | "Music"琴谱书堆、小猫摆件；台灯、笔筒、绿植用书房已有的 | 可选 | 每件 ≤ 1k |

- 拆分原则：**会动的、会变色的单独成物体**（5 个可弹键）；其余尽量合并，减少 Quest 上的渲染批次。
- 指尖光点、琴键发光、键名 / 指法数字、乐谱，都在 Unity 里做，不建模。

## 5. 不在 Blender 里做：乐谱 UI（记给 Unity 会话）
参考图上的浮空乐谱很适合当作 L2 的视觉提示，但要按 docs/12 的规则改：
- 显示**指法数字**（1–5），当前音高亮，下一个音淡亮，加一条进度条。
- 整块乐谱属于**视觉提示**：关掉 Visual 时（L3 测试常用）**整块隐藏**，不然患者看着乐谱就知道按哪根手指。
- **不显示对错颜色**（不用红 / 绿），只显示"当前位置"。
- 用 T1 的步骤卡片风格（Figma "HexR Learning UI"），高亮色用 Figma 的青色 `#00B4C7`，和琴键发光一致。

## 6. 风格
- 跟随 `art-brief.md`：低多边形、圆角倒角、平滑着色、哑光、调色板贴图 + 烘焙 AO。
- 外壳用深色暖灰或深木色（不要纯黑），白键用奶白色 `#F7F3EA` 左右，黑键用深炭色。
- 键的边缘做小倒角（1 mm）。键缝要看得出来，但不要太深，近看会闪。

## 7. 摆放
- 校准后琴的位置跟着患者的手走，**场景里不固定**。书房桌面中间 0.9 × 0.5 m 的操作区放得下。
- 琴前面要留约 12 cm 空桌面，给手掌和手腕放。

## 8. 交付
- Blender 文件：`art/blender/HexR_T2_Piano.blend`，集合 `T2_Keyboard`、`T2_Props`、`Preview_Only`（预览用的桌子、灯、相机，不导出）。
- 导出 FBX 到 `Assets/Art/Props/T2/T2_Keyboard.fbx`（道具一个文件），用 T11 那样的构建 / 导出脚本：`art/scripts/build_t2_piano.py`、`art/scripts/export_t2.py`。
- 导出后写一页 `docs/art/t2-piano.md`：实测尺寸、层级、导入步骤（同 `t11-bottles.md`）。
- Unity 会话负责：
  1. 换掉 `Learning_T2/Keyboard` 下的白模，重新指定 `keyPivots` / `keyRenderers` = `Key_C`…`Key_G`，`blackKeys` 清空；
  2. 给 `PianoKeyboard` 加"模型模式"：按患者指距缩放整台琴的 X，不再移动单个键；
  3. 校准后把虚拟桌面对齐到琴底；
  4. 做乐谱 UI。
