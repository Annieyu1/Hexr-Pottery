版本:v0.1 · 2026-10-08 · 分支 `feature/m2-pressure-demo`

目标:先做一个**玩法验证用的 Demo**(灰盒、不做美术),确认"两个物体、反复抓握、选更强"这套玩法对健康人成立、数据可用;之后再做场景美术与世界观。训练核心(M1)暂缓,Demo 内的试次逻辑写成**不依赖 Unity 的纯 C# 类**,以后原样搬进 Core。

## 1. 现有 Stage3 代码评审

读了 `ForceBall`、`ForceSortingZone`、`ForceStageController`、`FruitItem`,以及 `Meta.unity` 里的序列化值。

| # | 发现 | 影响 |
|---|---|---|
| 1 | **每个试次的球强度从不改变**:`ForceBall.Configure()` 没有被任何人调用,三个球的强度在 Inspector 里写死 | 每轮都一样,患者靠记忆位置就能答对,测不到触觉 |
| 2 | 场景里三个球的等级是 **Strong、Medium、Medium**,没有 Weak | 配置错误,分拣任务本身就无法全对 |
| 3 | 球的抓取手指:ring、pinky **关闭**(只开 thumb/index/middle/palm) | 不是"整只手"感受 |
| 4 | 结算靠 `OnTriggerEnter`:球碰到区域就算"放入",无确认 | 扔、掉落、路过都会误判;对手抖患者尤其不稳 |
| 5 | 球是带 Rigidbody 的物理球,松手会滚走 | 滚出桌面、够不着,耗时且让患者挫败 |
| 6 | 只记录内存里的 `trialResults`(试次号、答对数、百分比) | 不写文件;没有反应时间、抓握次数/时长、刺激值、位置 |
| 7 | 状态机只有 Playing → ShowingResult(固定 5 秒)→ 下一轮 | 无学习/测试阶段、无难度、无阶梯、无结束 |
| 8 | `FruitItem` 在场景里没有使用;它的强度表(15/30/60)与 `ForceBall` 的(10/35/60)不一致 | 重复代码,删除其一 |
| 9 | 文本是中英文混在注释和日志里、`Debug.Log` 很多 | 无功能影响,整理时统一 |
| 10 | 力度只存在于 Inspector 的 `strength`,没有任何运行时"当前刺激值"的出口 | 无法做学习期力度进度条,也无法记录 |

结论:**抓取 + 触觉这半边(`Grabbable` + `HandGrabInteractable` + `HexRInteractableHaptics`)可以直接复用;"分拣区域 + 三球 + 固定等级"这半边要换成 2AFC 试次逻辑。**

## 2. Demo 玩法规格

### 2.1 场景布局
- 桌面上两个**外观、大小、材质、重量感完全一致**的物体,分别在左、右底座上;
- 每个底座下方一个**大按钮**(戳选);
- 前方一块 UI 面板:提示语、试次进度、反馈。

### 2.2 一个试次
1. **呈现**:提示"Which one feels stronger? / 哪个压力更强?";
2. **探索**:患者可以**无限次**抓握任意一个物体、放开、再抓另一个。抓住时整只手感受该物体对应的压力;放开后物体自动回到底座;
3. **作答**:戳下面的按钮选择一侧(选择前不限制抓握次数,无倒计时);
4. **判定与反馈**:正确/再试一次(中性语言),短暂显示;学习阶段同时揭示两个物体的真实力度;
5. **记录**,进入下一试次。

### 2.3 刺激
- 基准强度 `S`:在 {25, 30, 35} 中随机(避免总拿同一个值当参照);
- 比较强度 `C = S + Δ`;较强的物体是 `C`,**左右随机**(连续同侧不超过 3 次);
- 单位是 HexR `strength`(可用范围 10–60,上限 60)。`C ≤ 60`。

难度表(Δ 以 `strength` 为单位,Weber 比 = Δ/S,按 S=30 估算):

| 难度级 | Δ | Weber 比 |
|---|---|---|
| 1 | 25 | 83% |
| 2 | 18 | 60% |
| 3 | 12 | 40% |
| 4 | 8 | 27% |
| 5 | 5 | 17% |
| 6 | 3 | 10% |

> 这些数是**占位**,真正的范围要靠健康人预试(第 6 节)确定;硬件对 3 个 strength 单位是否可分辨还未知。

### 2.4 阶段
| 阶段 | 内容 |
|---|---|
| 学习期 | 前 N 个试次(默认 8):难度 1–2;抓握时 UI 力度进度条显示当前物体力度;作答后显示两者真实值 |
| 测试期 | 无进度条;难度由**简单阶梯**调节(连续 2 对 → 难度 +1;1 错 → 难度 −1) |
| 结束 | 达到试次数(默认 40)或时间(默认 10 分钟)→ 汇总:正确率、最难通过的难度级;导出 CSV |

### 2.5 抓取手感相关规则
- 物体设为抓取后无重力漂移;**松手后 0.5 秒内平滑回到底座**(不靠物理滚动);
- 抓取判定放宽(轻抓即可);
- 压力在 `Select` 开始时施加,`Unselect` 时停止;
- 打开 ring、pinky、palm,整只手感受。

## 6. 健康人预试(Demo 完成后立刻做)

目的:确定**有效范围与起始难度**,不是做统计。

1. 找 3–5 位健康志愿者(含你自己),单手戴手套;
2. 每人做一轮测试期(固定每个难度级 6 个试次,不用阶梯),记录各难度级正确率;
3. 看:哪一级开始接近随机(50%)?3 个 `strength` 单位的差能否区分?`S` 的哪个值最敏感?
4. 看体验:抓握是否顺手?按钮是否好戳?有没有"其实看出来了"的视觉线索?有没有疲劳?
5. 结果填回难度表,并更新 03、05。

## 7. 验收标准

- [ ] 一个完整会话(学习 8 + 测试 40)能在 Quest 3 + 手套上跑完,无需编辑器;
- [ ] 每个试次一行 CSV,字段齐全,导出可打开;
- [ ] 左右随机,同侧不超过 3 次;
- [ ] 物体外观完全一致(截图对比);
- [ ] 学习期有力度条,测试期无;
- [ ] 松手后物体回位,不会滚落;
- [ ] 健康人预试至少 3 人,得出有效难度范围。
