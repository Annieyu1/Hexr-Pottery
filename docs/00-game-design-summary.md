# 项目与游戏设计总览(交接版)

更新:2026-10-14 · 给新会话/新成员的**一页入口**。细节在 `docs/01–09`、`OPEN_QUESTIONS.md`、`docs/art/`;本页只留结论和现状。与旧文档冲突时**以本页为准**(旧文档写于 10-08,部分状态已过期,见第 11 节)。

## 1. 是什么
为**轻中度中风患者**做的**手部触觉感知辨别康复训练**游戏(Quest 3 + Microtube HexR 触觉手套)。治疗师在临床使用,同时采集科研数据。先做**科研版**,之后裁剪出转化版。首个落地:新加坡 pilot,**离线、本地存储**。最终目标是**只靠触觉**判断,学习初期可用视觉辅助。

## 2. 硬件与触觉能力(设计的边界)
- 头显 Quest 3;Unity **6000.6.0f1**,URP 17.6,Meta XR SDK 205(OVR 路线);手套包 `com.microtube.hexr` v0.9.3。
- HexR 是**气动手套**,6 个通道:拇指、食指、中指、无名指、小指、手掌。
- 能做的触觉:
  | 类型 | 参数 |
  |---|---|
  | **压力** | 项目里用 `strength` 10–60(接口 0.1–1),逐指,可调变化速度 |
  | **振动** | 频率 **0.1–40 Hz**,强度 0.1–1 |
  | **整形低频振动** | ≤2 Hz,峰值比 0.2–0.8,结束后可保持一个压力 |
  | **脉冲** | 频率、强度、次数 1–1000 |
- **不能做的**:真正的力反馈(挡住手腕/手指运动)。"阻力感"只能用**压力随扭矩/抓握变化**来模拟。高频(>20 Hz)振幅是否衰减,**未实测**。
- 没有手套时用**模拟手套**在 Meta XR Simulator 里跑流程。

## 3. 三个游戏(各一个场景,内部分难度级)
| # | 感知维度 | 刺激 | 难度参数 |
|---|---|---|---|
| 1 | **压力力度分辨** | 单指/多指压力强度 | 基准强度、相邻差 ΔI/I、候选数、辅助级 |
| 2 | **振动频率/pattern 分辨** | 频率 0.1–40 Hz 或节律 | 基准频率、Δf/f、时长、候选数 |
| 3 | **手指定位分辨** | 触觉落在哪根/几根手指 | 手指数量、相邻与否、同时刺激数 |

训练时长暂定 **30 分钟 = 3 × 10 分钟**,不强制休息,**待治疗师确认**。

## 4. 范式与难度
- **初级:二选一(2AFC)**;**中级:三选一找不同(3AFC)**;高级暂不做。
- **2AFC 的呈现**:场景里**两个外观完全一样的物体**,只有左右位置不同,患者可**反复抓握、来回比较**(用整只手),固定问"**哪个压力更强**";目标左右随机并记录。
- 手指定位游戏不做"比较",初级是"2 根里选哪根被刺激",中级 3 根。
- **不要同时升两个维度**(范式变难 + 辅助撤除),否则失败原因分不清。
- 阈值方案(1 上 2 下 / 1 上 3 下、训练指标还是独立评估)**待定**。

## 5. 视觉辅助
- 视觉辅助**只在 UI 上**(例如抓握对应的力度进度条),**只出现在学习阶段**;**不改变物体外观**。首版只做两档:有(学习)/无(正式)。
- 要真正移除视觉线索:物体外观完全一致、不显示触点位置;形状类任务用布袋/盒子遮住物体。

## 6. 反馈与体验
- 反馈 = **视觉(文字、特效)+ 声音**;**不做触觉反馈**(会混淆被测刺激,是否有用未知)。
- 中性语言(不用"错误/失败"),错误后可**重新感受**正确与错误刺激并列重放;连续失败自动降难度/提示治疗师;不设单试次倒计时;随时可暂停。
- 目标正确率约 **70–80%**;不做故事、奖励系统;画面有趣但低刺激,避免高频闪烁。

## 7. 数据与治疗师界面
- 会话级 `session.json`(受试者匿名码、手别、版本、配置快照、校准、不良事件等)+ 试次级 `trials.csv`(刺激值、位置、反应、反应时间、探索次数/时长、难度/辅助级、异常标注),**逐行 flush,先写数据再做表现**。
- 派生指标:正确率、阈值、反应时间、探索行为、位置偏差、视觉依赖度、学习曲线。
- 治疗师界面一期方案待定(倾向:配置+查看+导出 + 投屏),入口避免被患者误触。

## 8. 架构(目标)
`Games`(场景、交互、表现)→ `Training Core`(`TrialRunner`、`Stimulus`、`AdaptiveProcedure`、`SessionManager`、`FeedbackDirector`)→ `Haptics`(`IHapticDevice`:真实/模拟手套)+ `Data`(`DataLogger`)→ 平台(Meta XR、HexR)。原则:游戏与训练科学分离、手套可替换、**配置驱动**、数据优先、单人维护少抽象。场景流:`Boot → Hub → 三个游戏 → 回 Hub`,治疗师入口隐藏。

## 9. 当前实现状态(2026-10-14)
- **M2 压力 2AFC Demo**已在仓库(`Assets/PressureDemo`,命名空间 `HexRMeta.Pressure`):两个 `PressureObject`(左右)、`StrongerZone` 感应垫(`AnswerZone`:松手后在区域内**停留约 0.5 秒**才算作答,可改主意)、`PressureGameController` 驱动试次,含暂停/恢复。
- 物体**松手 0.5 秒后若不在感应垫内,平滑回原位**(原位 = 进场景时位置);掉出桌面瞬移回位;被抓握时不归位;暂停时物体回位且手套静音。
- 试次逻辑是不依赖 Unity 的纯 C# 类(`Logic/`),以后可搬进 Core。
- **M1 训练核心**(`TrialRunner`、阶梯法、`DataLogger`…)**尚未做**,Demo 先验证玩法。

## 10. 任务扩展:日常生活感知任务(方案,未实现)
把三个范式放进**日常物体**,同一间书房/花园桌面:
| 任务 | 日常动作 | 触觉设计 | 对应 |
|---|---|---|---|
| A 杯子谁更满 | 拿起两个一样的杯子比"水量" | 抓握压力 = 20 + 水量×25(落在 10–60) | 游戏 1,2AFC→3AFC |
| B 水晃得快不快 | 端杯晃动 | 食指/中指叠加低频整形振动,水越满越慢(约 0.8→2 Hz) | 游戏 2 |
| C 拧盖子 | 拇指食指捏住转开 | 压力随扭矩升高(紧盖≈50、松盖≈25);每转 15° 脉冲"咔哒"(约 30 Hz);松开时一次 40 Hz 短振;不同盖型=不同触感 | 游戏 1+2 |
| D 摸形状 | 手伸进布袋摸杯形 | 形状编码成 6 通道压力分布(**需学习,学习阶段给 UI 提示**) | 游戏 3 |
建议顺序 A → C → B → D。**需先确认**:患者拇指-食指能否捏合;单手还是双手;同一根手指能否同时有压力+振动(上机测);测阈值还是训练。

## 11. 美术与场景
- **两个场景风格**,都是"柔和温馨",按场景分:
  - **书房**(`art/blender/HexR_StudyRoom.blend`,Unity 场景 `Pressure_Demo_Room`):低多边形、哑光、暖色调、烘焙灯光。详见 `docs/art/art-brief.md`。
  - **花园小岛**(`art/blender/HexR_Garden.blend`):**不要低多边形**,粗壮圆润、有倒角、软渐变、暖金色调。详见 `docs/art/garden-brief.md`。
- 第三方模型只收 **CC0 / CC-BY**,记入根目录 `ASSET_CREDITS.md`。
- Quest 预算:可见三角面 15–20 万以内,帧率 72 Hz;材质合并成调色板图集;烘焙光照;小而碎的物件用光照探针。
- Blender 导出管线:`art/scripts/export_room.py`(→ `Assets/Art/Environment/*.fbx`),`palette.py` 合并材质。
